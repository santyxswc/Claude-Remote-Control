# F12: Session summary and memory

## Objective

Close a session from the phone. `/wrap` asks Claude for a summary of the session, which the
bridge saves in `docs/sessions/`, and for a few lines worth keeping in the project's `CLAUDE.md`.
The owner approves or rejects those lines with a button. Nothing enters `CLAUDE.md` without that
tap, and the bridge, not Claude, writes both files. Decisions:
[ADR 0015](../adr/0015-session-summary-and-memory.md). Plan acceptance: a full session ends with
an approved summary saved.

## Steps

1. **`/wrap`** (`WrapCommand`, `RequestSessionWrap`).
   - One fixed catalog instruction (`wrapInstruction`, Spanish or English, nothing interpolated)
     goes into the full inbound chain as text from the owner: rate limit, brake gate, audit
     `wrap.requested`.
   - The chat gets "Asked Claude to summarize the session...". While braked nothing is sent
     and the bot says the brake is engaged.
   - The instruction asks Claude to call `save_session_summary` with the chat id of that
     message, then `propose_memory` with at most 8 one-line items if anything is worth keeping,
     and never to edit `CLAUDE.md` itself.
2. **`save_session_summary({chat_id, title, markdown})`** (`SaveSessionSummary`,
   `FileSessionSummaryStore`).
   - The chat follows the `reply` rule, without the dev chat.
   - The title is sanitized to one line of at most 120 characters. The text is cleaned: CRLF to
     LF; controls (except newline and tab), bidi and zero-width characters removed. It is at most
     200,000 bytes, and `# <title>` is prepended unless the text starts with a level-one heading.
   - The file name is `<yyyy-mm-ddThhmmssZ>-<slug>.md` in UTC, with no colons (Windows). The
     slug comes from `summarySlug` (domain): accents dropped, `[a-z0-9-]`, at most 60
     characters, `session` when empty.
   - The project is `CLAUDE_PROJECT_DIR` when absolute, else the channel's working directory.
     `docs/` and `docs/sessions/` are created level by level, and a link (symlink or junction)
     resolving outside the project is refused. The file is created with `wx`: never overwritten,
     never a link followed. A collision tries `-2`, `-3`, ... up to 50.
   - The chat gets "Summary saved to <path> (local file, not redacted)" and the summary through
     the text pipeline (redacted and split). Above 16,000 characters it gets only the path and
     the length.
   - The tool returns the relative path. Audit `session.summary_saved` (chat, bytes, notified) or
     `session.summary_not_saved` (reason).
3. **`propose_memory({chat_id, lines})`** (`ProposeMemory`, `MemoryPrompts`).
   - The chat follows the `reply` rule. Only the polling process can ask (`not_polling`
     otherwise).
   - `checkMemoryLines` (domain): 1 to 8 lines, trimmed, non-empty, at most 300 code points;
     no control (tab and line separators included), bidi or zero-width character, code fence or
     HTML comment marker. The error names the line (1-based).
   - The proposal is stored as pending and the prompt sent: the lines as bullets, then
     Approve and Reject (`m1:<id>:a`, `m1:<id>:r`). It is sent with `redaction: 'refuse'` and
     `overflow: 'refuse'`. A line that redaction would change gives `contains_secret`, and lines
     that do not fit one message give `too_long_for_one_message`. Either way the proposal is
     cancelled and the tool returns an error.
   - The tool returns `proposed; proposal_id=<id>` at once. Audit `memory.proposed` (id, chat,
     line count, characters) or `memory.refused` (reason, line count).
4. **The tap** (`ButtonTapHandler`, `ResolveMemoryProposal`).
   - After the handler's checks (private chat, own chat, allowlisted sender, rate limit), the
     anchored `m1:` parser routes it. The use case checks the allowlist again, the session and
     the chat.
   - Past 30 minutes the proposal expires.
   - **Approve:** claim with compare-and-set. `ClaudeMdMemoryFile` then appends the bullets
     under `## Session notes` (`appendSessionNotes`: the heading is created once at the end; the
     bullets join an existing section before the next `#`/`##` heading; a heading inside a code
     fence does not count; CRLF and a BOM are kept). The write is atomic: a temp file next to
     the real one, `fsync`, `rename`, the mode kept. It refuses a link resolving outside the
     project, a non-regular file, a file over 1 MB, or a file that changed meanwhile. A failed
     write reopens the proposal and is audited `memory.write_failed`. On success:
     `memory.approved` (id, line count).
   - **Reject:** nothing is written; `memory.rejected`.
   - Either way the message is edited (the lines plus "✅ Approved by ...: written to CLAUDE.md" or
     "❌ Rejected by ...: nothing was written"), the buttons go, and the session gets a fixed channel message with
     `kind="memory"` and `proposal_id`. While braked the approval still writes but nothing is
     forwarded, and the toast says so.
   - A second tap only gets a toast ("That proposal was already resolved").
5. **Expiry** (`ExpireMemoryProposals`). The 5 s sweep expires this session's proposals after 30
   minutes. When the poller lock is taken, other sessions' proposals are cancelled. Both edit the
   message and remove its buttons; nothing is written or forwarded.
6. **Risk rules** (`RiskPolicy`, high risk, F3 second tap):
   - `memory_file_edit`: `Write`/`Edit`/`MultiEdit`/`NotebookEdit` on `CLAUDE.md`,
     `CLAUDE.local.md`, `AGENTS.md` or under `.claude/`, in any case, with `\` or `/`.
   - `memory_file_write`: shell redirections and file-writing commands into those paths.
7. **Session end.** There is no automatic wrap. A `SessionEnd` hook cannot make Claude do work:
   the docs say it has no decision control, its output fields are discarded and it times out
   after 1.5 s (ADR 0015). `hooks/hooks.json` is unchanged.

### The instruction (fixed text, `messages.ts`)

> The owner sent /wrap in Telegram to close this session. 1) Write a concise Markdown summary of
> the session (what was done, decisions and why, open items and next steps) and save it with the
> save_session_summary tool, using the chat_id of this message and a short title. Do not write
> the file yourself. 2) If there are durable lessons worth keeping for future sessions in this
> project (conventions, commands, pitfalls), propose them with the propose_memory tool: at most
> 8 short items, one line each. Do not edit CLAUDE.md yourself: only the lines the owner approves
> with the button are written. If nothing is worth remembering, skip step 2 and say so in your
> reply.

## Acceptance

- `tests/acceptance/F12.test.ts` uses the real composition, the fake Bot API and a temp project:
  - `/wrap` delivers exactly the catalog instruction; braked, it delivers nothing.
  - `save_session_summary` writes `docs/sessions/2026-11-14T103005Z-revision-de-f12.md`. The
    chat notice is redacted; the file is not.
  - `propose_memory` then Approve appends to a CRLF `CLAUDE.md` byte for byte and leaves no
    temp file. The session gets `kind="memory"`, the buttons go, a second tap changes nothing,
    and the audit has counts only.
  - Reject writes nothing. An `m1:` tap is never a permission verdict. Braked, Approve writes
    and nothing is forwarded. A line with a token is refused and nothing is stored as pending.
    An expired proposal loses its buttons and a late tap writes nothing.
- Adapters: `tests/adapters/project/projectFiles.test.ts` covers creation, no overwrite,
  collisions, `docs`/`sessions` junctions or symlinks leading outside (refused, nothing written
  there), an inside link (allowed), CRLF, mode, the size cap, a directory named `CLAUDE.md`, and
  file symlinks outside and inside. File symlinks are skipped where the OS refuses them (Windows
  without the privilege); junctions run everywhere. `tests/adapters/storage/SqliteMemoryProposalStore.test.ts`
  covers the store.
- Domain and application: `tests/domain/memory/`, `tests/domain/sessions/`,
  `tests/domain/permissions/memoryRisk.test.ts`, `tests/application/use-cases/memoryUseCases.test.ts`,
  `SaveSessionSummary.test.ts`, the `m1:` routing in `ButtonTapHandler.test.ts`, and the tools in
  `tests/adapters/mcp/f11f12Tools.test.ts`.

## Sequence

```mermaid
sequenceDiagram
    actor P as Owner (phone)
    participant IN as Inbound chain
    participant CC as Claude Code
    participant MCP as McpChannelServer
    participant PM as ProposeMemory
    participant DB as memory_proposals (SQLite)
    participant T as ButtonTapHandler
    participant RM as ResolveMemoryProposal
    participant FS as CLAUDE.md

    P->>IN: /wrap
    IN->>CC: fixed instruction (as owner text)
    CC->>MCP: save_session_summary {chat_id, title, markdown}
    MCP-->>P: "Summary saved to docs/sessions/..." + summary (redacted)
    CC->>MCP: propose_memory {chat_id, lines}
    MCP->>PM: execute
    PM->>PM: chat rule, polling, checkMemoryLines
    PM->>DB: put (pending)
    PM->>P: lines + Approve/Reject (m1:), refused if redaction or overflow
    PM-->>CC: proposed; proposal_id=<id>
    P->>T: tap m1:<id>:a
    T->>RM: execute (never ResolvePermission)
    RM->>DB: approve (compare-and-set)
    RM->>FS: append under "## Session notes" (temp + rename)
    alt not braked
        RM->>CC: channel message kind=memory, proposal_id
    end
    RM->>P: edit: approved, no buttons
```

## Manual verification (owner, with a token and a paired account)

1. In a project with a `CLAUDE.md`, do some work, then send `/wrap`. Allow the two tools when
   prompted. Record whether Claude calls both, with the right `chat_id`.
2. The chat gets the path and the summary; the file exists under `docs/sessions/`.
3. The proposal shows every line with Approve and Reject. Approve: `CLAUDE.md` ends with
   `## Session notes` and the bullets; `git diff CLAUDE.md` shows only added lines. The session
   gets the `kind="memory"` message: record that Claude does not write the lines again.
4. `/wrap` again, Reject: nothing changes.
5. Ask Claude to edit `CLAUDE.md` directly: the permission prompt says HIGH.
6. Leave a proposal 30 minutes: "Expired", nothing written.
7. Audit query: `wrap.requested`, `session.summary_saved`, `memory.*` rows with ids and counts
   only.

## Open points

- The summary file is not redacted (the chat copy is). It is inside the project and may be
  committed; the chat notice says so.
- `changed_meanwhile` compares size and modification time only.
- `/wrap` relies on Claude following the instruction; nothing forces it to call the tools.
