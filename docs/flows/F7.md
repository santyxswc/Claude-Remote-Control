# F7: Options and skills

## Objective

Two ways to answer with a tap instead of typing:

- **`ask_choice`.** An MCP tool that lets Claude ask a multiple-choice question. The user taps
  a button, and the label reaches the session as a normal message.
- **`/skills`.** A chat command that lists the session's skills as buttons. A tap asks Claude to
  use that skill.

Both only produce text for the session. A choice is never a permission verdict and never skips
the permission relay (F3) or the brake (F6). Decisions: [ADR 0011](../adr/0011-choices-skills-and-attachments.md).

## Steps

### `ask_choice`

1. **The tool** (`src/adapters/mcp/McpChannelServer.ts`). Arguments:
   - `chat_id`;
   - `question` (1 to 16,384 characters);
   - `options` (2 to 8 strings);
   - optional `allow_other`.

   It is listed only with a bot token and the allowlist (the same condition as the permission
   relay). It returns `asked; choice_id=<id>` at once and does not wait for the answer. A process
   that does not hold the poller lock answers `not_polling`.
2. **Checks** (`AskChoice`):
   - The chat follows the `reply` rule (`AuthorizeReplyTarget`): the private chat of a currently
     allowlisted sender, with no dev chat. Refusals are audited as `choice.refused`.
   - The question is sanitized (`sanitizeMultilineText`: controls, bidi overrides and invisible
     characters removed; lines kept).
   - Labels are sanitized to one line and must be non-empty, at most 64 code points (never cut,
     since a cut label could pass for another) and unique ignoring case. Problems come back as a
     tool error naming the rule.
3. **State** (`src/domain/choices/Choice.ts`, GoF State style). The states are:
   - `pending` → `answered` (an option was tapped);
   - `pending` → `awaiting_text` ("Other…" was tapped) → `answered`;
   - any open state → `expired` (30 minutes) or `cancelled` (its session is gone).

   Every transition bumps a revision, and `SqliteChoiceStore` writes with compare-and-set, so a
   double tap or a racing expiry delivers only once. The question and labels are kept only while
   the choice is open; closed rows keep ids, the state, the chosen index and who answered.
   The table is migration 3 in `src/adapters/storage/sqlite.ts`.
4. **The message** (`ChoicePrompts`):
   - One message with one button per option (one per row) and "Other…" when allowed, sent
     through `buildOutbound` (`RedactingPromptGateway` redacts the text and every button label).
   - Button data is `c1:<id>:<0-7|o>`. The id is 10 base32 characters (50 random bits), so the
     data is at most 15 bytes.
   - A question that does not fit one message once redacted follows the long-content rule from
     F3: it goes first as plain messages (redacted, chunked), then the buttons with "the full
     question is in the message above".
5. **A tap** (`ButtonTapHandler` → `AnswerChoice`):
   - Same authentication as permission taps: private chat, the chat is the sender's own, `from.id`
     is allowlisted, rate limit. The use case checks the allowlist again.
   - The data is routed by its prefix. Each parser is anchored and strict: `p1:` reaches only
     `ResolvePermission`, `c1:` only `AnswerChoice`, and `k1:` only the skills menu.
   - The choice must belong to this session and to the tapped chat.
   - If the brake is engaged, the tap gets the brake toast and nothing changes.
   - An option: the answer is stored, then the label is delivered with `HandleInboundMessage` (as
     typed text is, with the "queued" note and the `message.forwarded` audit). The meta carries
     `chat_id`, `user`, `kind="choice"` and `choice_id`. The message is edited to "✅ Chosen: …"
     and loses its buttons. If delivery fails, the choice is open again.
   - "Other…": `awaiting_text`. The message says "write your answer as your next message".
6. **The typed answer** (`ChoiceTextAnswerStep`, after the brake gate and the commands). The next
   text from that chat answers the newest waiting choice of this session. It is forwarded with
   `kind="choice"` and `choice_id`, and the choice closes. Commands (`/stop`, `/status`) are never
   taken for the answer. While braked, the text stops at the gate and the choice keeps waiting.
7. **Expiry.** The 5-second permission sweep also expires due choices and edits their message.
   When this process takes the poller lock, the open choices of other sessions are cancelled
   (ADR 0007, same as permission requests).
8. **Audit.** The events are:
   - `choice.asked` (id, chat, number of options, `allowOther`);
   - `choice.refused`;
   - `choice.answered` (id, `via` button or text, the option index);
   - `choice.expired` (id, reason).

   The question and the labels are never audited.

### `/skills`

1. **Where skills come from** (port `SkillFiles`, adapter `DiskSkillFiles`).
   - Personal skills: `<Claude config dir>/skills/*/SKILL.md`. The config dir is `CLAUDE_CONFIG_DIR`
     or `~/.claude`, resolved like the state directory: a relative value is refused.
   - Project skills: `<project>/.claude/skills/*/SKILL.md`. The project is `CLAUDE_PROJECT_DIR` when
     it is absolute, otherwise the working directory if it has `.claude/` or `.git`, otherwise
     unknown.
   - Read-only and defensive: at most 500 directories per root, files over 64 KiB skipped, dot
     directories skipped, and anything whose real path (symlinks resolved) leaves its root is
     skipped and logged. Plugin skills and nested or `--add-dir` skills are not listed (see
     Deviations).
2. **Parsing** (`src/domain/skills/skillFrontmatter.ts`). A tiny reader for the frontmatter:
   - it must start on line 1, within 200 lines, with a closing `---`;
   - only top-level `key: value` lines, plain or quoted scalars, and `|` / `>` blocks (read as one
     line);
   - nothing is evaluated.

   `name` falls back to the directory name and must match `^[a-z0-9][a-z0-9:_-]{0,63}$`. A
   `user-invocable: false` skill is hidden, like in Claude Code's `/` menu. The description is
   sanitized and capped at 1,536 characters. A personal skill wins over a project skill with the
   same name.
3. **The menu** (`SkillsMenu`, `SkillsCommand`):
   - One message with a line per skill (`• name - description`, the description shown up to 90
     characters) and one button per skill.
   - Eight per page, with Previous and Next buttons that edit the message.
   - Button data is `k1:<8-hex key of the name>` or `k1:p<page>`.
   - With no skills it says so. When the project directory is unknown, the menu (or the empty
     reply) says that only personal skills are listed.
4. **A tap** (`RequestSkill`):
   - The skills are read again from disk, and the key must still match one.
   - The use case checks the brake first, to show the brake toast.
   - Then `Use the skill /<name>` is fed to the inbound chain as text from the owner, exactly like
     typing it: rate limit, brake gate, audit, typing status.

### The wording `Use the skill /<name>`

The channel reference documents channel events as text that Claude reads. It does not say that a
`/name` inside a channel event runs as a slash command the way the terminal runs one. A bare
`/name` could also be mistaken for one of the bot's own commands. So the tap sends an instruction
that works either way: as prose, Claude reads "Use the skill /deploy" and invokes the skill with
its Skill tool (skills are model-invocable unless `disable-model-invocation: true`). **Whether a
slash command in a channel event runs directly needs live verification** (checklist, Part 8). A
skill with `disable-model-invocation: true` may not run from the chat at all; that also needs to
be checked live.

## Deviations

- **Plugin skills are not listed.** Their install location belongs to Claude Code. Nested
  `.claude/skills` directories and `--add-dir` skills are not listed either. The menu shows what
  `DiskSkillFiles` can find with certainty.
- **Block descriptions** (`|`, `>`) are joined into one line; the menu shows one line anyway.
- **"Other…" answers the newest waiting choice** of the chat. Two choices waiting for text at once
  are answered newest first.

## Acceptance

- `tests/acceptance/F7.test.ts` runs the real MCP server, SQLite, grammY poller, inbound chain and
  outbound decorators against the fake Bot API, with skills in temp directories:
  - a tap delivers the label once with `kind`/`choice_id`/`chat_id`/`user`; the message loses its
    buttons; a second tap says "already answered"; the audit has no question or labels;
  - a choice tap never produces a permission verdict, even with a permission request pending
    under an id that appears in the labels; forged data does nothing;
  - stranger and group taps are dropped without an answer;
  - while braked: brake toast, nothing forwarded; after `/resume` the tap works;
  - "Other…" and the next text, with `/status` in between not taken as the answer;
  - no "Other…" button without `allow_other`, and a forged one does nothing;
  - expiry after 30 minutes; orphan choices cancelled when polling starts;
  - invalid arguments and other chats refused with nothing sent;
  - secrets and bidi characters removed from the question and labels; a very long question goes
    above the buttons;
  - `/skills`: project and personal skills, hidden and badly named ones skipped, a tap sends
    `Use the skill /deploy`, a braked tap sends nothing, pages above 8, unknown project.
- Unit tests:
  - the `Choice` entity and normalization (`tests/domain/choices/`);
  - the frontmatter parser (`tests/domain/skills/`);
  - the callback data, all four choice use cases and `ChoicePrompts`
    (`tests/application/use-cases/choiceUseCases.test.ts`);
  - `ListSkills`, `RequestSkill` and the menu (`skillUseCases.test.ts`);
  - routing in `ButtonTapHandler.test.ts`;
  - `ChoiceTextAnswerStep`;
  - `SqliteChoiceStore`;
  - `DiskSkillFiles` (symlinks out of the root, oversize, dot dirs) and `resolveProjectDir`;
  - the `ask_choice` tool schema and results;
  - label redaction in `RedactingPromptGateway`.

## Sequence

```mermaid
sequenceDiagram
    participant CC as Claude Code
    participant MCP as McpChannelServer
    participant A as AskChoice
    participant DB as choices (SQLite)
    participant OUT as buildOutbound
    actor P as Owner (phone)
    participant T as ButtonTapHandler
    participant AC as AnswerChoice
    participant F as HandleInboundMessage

    CC->>MCP: tools/call ask_choice {chat_id, question, options}
    MCP->>A: execute
    A->>A: chat rule, sanitize, validate
    A->>DB: put (pending)
    A->>OUT: sendPrompt (redacted text and labels)
    OUT->>P: question + buttons c1:<id>:<n>
    A-->>CC: asked; choice_id=<id> (returns at once)
    P->>T: tap c1:<id>:1
    T->>T: private chat, own chat, allowlist, rate limit, prefix c1
    T->>AC: execute
    alt brake engaged
        AC-->>P: toast "brake is engaged"
    else pending
        AC->>DB: update answered (compare-and-set)
        AC->>F: label, meta kind=choice, choice_id
        F->>CC: notifications/claude/channel
        AC->>OUT: edit "✅ Chosen: ...", no buttons
        AC-->>P: toast "Sent to Claude"
    end
```

## Manual verification

1. With the session running and the bot paired, ask Claude: "Ask me with ask_choice whether to use
   Postgres or SQLite, and allow another answer." Allow the tool when prompted. The phone shows the
   question with three buttons; the session already has `asked; choice_id=...`.
2. Tap SQLite. The toast says "Sent to Claude", the message shows "✅ Chosen: SQLite" without
   buttons, and the session gets a `<channel ... kind="choice" choice_id="...">SQLite</channel>`
   event. Tap the old message again: "already answered".
3. Ask again and tap "Other…", then type "MariaDB". The event carries the same `choice_id`.
4. Ask again, send `/stop`, tap an option: brake toast, nothing reaches Claude. `/resume`, tap:
   delivered.
5. Ask and leave it for 30 minutes: it shows "Expired".
6. Put a skill in `<project>/.claude/skills/hello/SKILL.md` with a `description`, send `/skills`,
   tap `hello`: the session gets "Use the skill /hello". Record whether Claude runs it, and how.
7. Start the session from a directory that is not a project, without `CLAUDE_PROJECT_DIR`: `/skills`
   says the project is unknown.
8. Audit query: `choice.*` rows without questions or labels.
