# F8: Git from the chat

## Objective

See what changed in the project from the phone, and ask Claude to act on it. `/diff` sends a
short summary and the uncommitted changes as a `.diff` file; three buttons under it (Commit,
Revert, Open PR) each send Claude a fixed instruction. The bridge itself only ever reads the
repository (ADR 0012). Plan acceptance: `/diff` returns the file, and Commit asks Claude to commit,
with the permission prompt as usual.

## Steps

1. **Domain** (pure).
   - `parseDiffPathFilter` (`src/domain/git/diffPathFilter.ts`): the optional `/diff <path>`.
     It accepts relative paths only, normalized to `/` with `.` and empty segments dropped, and
     refuses:
     - empty input, or more than 1024 characters;
     - C0/C1 controls (NUL and newline included), DEL, U+2028/2029 and bidi controls;
     - anything rooted: `/x`, `\x`, `C:x`, `\\server`;
     - any `..` segment;
     - a leading `-` (an option) or `:` (pathspec magic: `:(glob)`, `:!x`, `:/`), also after
       normalization (`./-x`).
   - `parseStatusPorcelainV2` and `parseNumstat` (`src/domain/git/gitOutput.ts`): branch,
     upstream, ahead/behind, staged/unstaged/conflicted counts, untracked paths, and per-diff
     totals (binary files counted apart).
   - `cutAtLineBoundary` and `keepCompleteLines` (`src/domain/lineCut.ts`): cut a text only
     between lines, so no secret is ever split in half.
2. **Ports.**
   - `GitRepository.read({ pathFilter?, withChanges, signal? })` returns one of:
     - `not_a_repo`;
     - `unavailable` (`git_missing` or `unsafe_config`);
     - `ok` with the status and, on request, the staged and unstaged patches and totals.
   - `DocumentGateway.sendDocument(chat, { filename, text, maxBytes, cutNote }, caption)`.
3. **Adapter `GitCli`** (`src/adapters/git/`).
   - Only the seven invocations of `gitInvocations.ts` exist (list below).
   - Each runs as an argument array, with no shell, in the project directory (`CLAUDE_PROJECT_DIR`,
     else the channel's working directory).
   - Each has a 15 s timeout, a read cap, and an environment scrubbed down to what git needs to
     find itself and the owner's configuration.
   - It reads `is_work_tree`, then the filter driver names, then `status`, then the four diffs in
     parallel.
   - A patch over 5 MB is read up to the cap and loses its partial last line. A filter name that
     cannot be overridden safely, or a filter listing too long to read whole, gives
     `unsafe_config`.
4. **Outbound.** `RedactingDocumentGateway` is built in `buildOutbound()`.
   - It redacts the whole text first.
   - Only then does it cut it to 5 MB between lines, with a note.
   - The caption is redacted and fitted to 1024 characters.
   - The document goes to Telegram only, never to the dev listener.
5. **Use case `ShowDiff`** (`/diff [path]`).
   1. The chat must pass `AuthorizeReplyTarget`.
   2. The path policy runs before any process.
   3. One `/diff` runs at a time; another while it runs is `busy`.
   4. It runs in the background (M1), and `stop()` cancels it (the git process is killed).
   5. No changes (no staged or unstaged patch and nothing untracked): it says so and sends no
      file.
   6. Otherwise it sends `changes.diff`. The content is the staged patch, the unstaged patch and
      the untracked paths, each one sanitized onto a single line (at most 2000 are listed). The
      caption is the summary: project, branch, ahead/behind, counts, files, +/−, binary.
   7. Then it sends one message with the buttons.
   8. Audit `git.diff_sent` or `git.diff_not_sent` with counts, sizes and the reason, never a
      path or content.
6. **Buttons** (`g1:<c|r|p|y|x>:<base-36 seconds>`, anchored regex in `gitCallbackData.ts`).
   - Routed by `ButtonTapHandler` after its checks: private chat, own chat, allowlisted `from.id`
     and the rate limit. Only `p1:` reaches `ResolvePermission`.
   - `RequestGitAction` handles them:
     - A tap more than 30 min old, or 2 min for the confirm step, is `expired`.
     - Braked: the brake toast, and nothing is sent.
     - Commit and Open PR feed one fixed catalog instruction into the full inbound chain as
       text from the owner, like a skill tap: rate limit, brake gate and audit
       (`git.action_requested`). The buttons are then replaced with "Sent to Claude: …".
     - Revert first swaps the buttons for "Confirm revert" / "Cancel". Only Confirm sends the
       revert instruction.
   - No instruction contains anything from the repository.
7. **`/status`** gains one line: `Git: branch main, ahead 1, behind 0 · 1 staged, 2 unstaged,
   3 untracked` (or "not a git work tree"). Git errors leave the line out.

### The instructions (fixed text, `messages.ts`)

| Button | English |
| --- | --- |
| Commit | The owner tapped "Commit" under /diff in Telegram. Review the current changes and create a commit with a clear message. Do not push. |
| Open PR | The owner tapped "Open PR" under /diff in Telegram. Push the current branch and open a pull request for it; report the URL. |
| Revert (after Confirm) | The owner tapped "Revert" under /diff in Telegram and confirmed it. Discard all uncommitted changes in the working tree (tracked files only; list untracked files instead of deleting them). |

They are instructions, not approvals. Claude decides how to carry them out, and every tool call it
makes still goes through the permission prompt (F3) and the brake (F6).

### Every git command line (`src/adapters/git/gitInvocations.ts`)

Each one starts with:

```
git --no-pager --no-optional-locks --literal-pathspecs
    -c core.fsmonitor=false -c core.hooksPath=<null device> -c core.quotePath=false -c color.ui=false
    -c protocol.allow=never
    [-c filter.<name>.clean= -c filter.<name>.smudge= -c filter.<name>.process= -c filter.<name>.required=false]...
```

The filter part repeats for each filter driver the configuration defines. The rest of the line is
one of:

| Invocation | Rest of the argv |
| --- | --- |
| `is_work_tree` | `rev-parse --is-inside-work-tree` |
| `list_filters` | `config --null --name-only --get-regexp ^filter\.` |
| `status` | `status --porcelain=v2 --branch -z --untracked-files=normal --ignore-submodules=dirty [-- <path>]` |
| `staged_numstat` | `diff --cached --numstat -z --no-ext-diff --no-textconv --no-color --ignore-submodules=dirty [-- <path>]` |
| `unstaged_numstat` | `diff --numstat -z --no-ext-diff --no-textconv --no-color --ignore-submodules=dirty [-- <path>]` |
| `staged_patch` | `diff --cached --no-ext-diff --no-textconv --no-color --ignore-submodules=dirty [-- <path>]` |
| `unstaged_patch` | `diff --no-ext-diff --no-textconv --no-color --ignore-submodules=dirty [-- <path>]` |

The environment of each command:

- **Kept** from the channel's environment, matched case-insensitively: `PATH`, `HOME`,
  `USERPROFILE`, `HOMEDRIVE`, `HOMEPATH`, `SYSTEMROOT`, `WINDIR`, `TEMP`, `TMP`, `TMPDIR`,
  `XDG_CONFIG_HOME`, `LANG`, `LC_ALL`, `LC_CTYPE`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`,
  `GIT_CONFIG_NOSYSTEM`.
- **Added**: `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `GIT_LITERAL_PATHSPECS=1`,
  `GIT_NO_LAZY_FETCH=1`.
- **Dropped**: everything else, including `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`,
  `GIT_EXTERNAL_DIFF`, `GIT_PAGER`, `PAGER`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`/
  `KEY_n`/`VALUE_n`, askpass and SSH variables, and the bot token.

What each part closes:

| Part | Vector closed | Source |
| --- | --- | --- |
| `diff --no-ext-diff` | `diff.external`, `diff.<driver>.command`, `GIT_EXTERNAL_DIFF` | git-diff: "Disallow external diff drivers." |
| `diff --no-textconv` | `diff.<driver>.textconv` | git-diff: "Allow (or disallow) external text conversion filters to be run when comparing binary files." |
| `-c filter.<name>.{clean,smudge,process}=`, `.required=false` | clean and process filters, which `diff` and `status` run on worktree files | `-c foo.bar=` "sets foo.bar to the empty string"; an empty command disables the driver. Without `required=false` a required driver makes git fail instead |
| `-c core.fsmonitor=false` | a `core.fsmonitor` hook command run by `status` | git-config `core.fsmonitor` |
| `--no-optional-locks`, `GIT_OPTIONAL_LOCKS=0` | `status` refreshing and writing the index, and with it a `post-index-change` hook | git: "equivalent to setting GIT_OPTIONAL_LOCKS to 0" |
| `-c core.hooksPath=<null device>` | any hook, from `.git/hooks` or a configured `core.hooksPath` | git-config `core.hooksPath` |
| `--no-pager` | `core.pager`, `pager.<cmd>`, `GIT_PAGER` | git: "Do not pipe Git output into a pager." |
| `--literal-pathspecs`, `GIT_LITERAL_PATHSPECS=1`, the path after `--` | the path read as an option, a glob or pathspec magic | git: "Treat pathspecs literally (i.e. no globbing, no pathspec magic)." |
| `--ignore-submodules=dirty` | git started inside submodules, under their own configuration | git-status / git-diff |
| `-c protocol.allow=never`, `GIT_NO_LAZY_FETCH=1` | a partial clone making `diff` fetch a missing object from its promisor remote, which would run `core.sshCommand`, `remote.<name>.uploadpack` or a remote helper | git-config `protocol.allow`; git: `GIT_NO_LAZY_FETCH` (2.45+) |
| `GIT_TERMINAL_PROMPT=0`, stdin ignored | a credential prompt that would hang | git: `GIT_TERMINAL_PROMPT` "false" means no prompting |
| no fetch, push or remote command at all | network | the invocation list |

**Verified** by `tests/adapters/git/GitCli.test.ts` on Windows 11 with git 2.55.0.windows.3. The
same test runs in CI on ubuntu and windows. Each temp repository has its own configuration
(global and system files pointed away):

- A **control** test runs plain `git status`, `git diff`, `git diff --cached` and `git add`
  against the hostile configuration, and markers appear. On the dev box these ran: `diff.external`,
  the filter clean and process drivers, `core.fsmonitor`, the `post-index-change` hook from
  `core.hooksPath`, and, in a second variant without `diff.external` or filters, a
  `diff.<driver>.command` and a textconv.
- The **adapter** test runs every read, with and without a path, against the same
  configuration, plus a hostile parent environment (`GIT_EXTERNAL_DIFF`, `GIT_PAGER`, `PAGER`,
  `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`). No marker appears, and no `index.lock` is left
  behind.

Flag texts were read on git-scm.com (git, git-diff, git-config, git-status) on 2026-11-14.

### Telegram limits

`sendDocument`: "files of any type of up to 50 MB in size"; caption "0-1024 characters after
entities parsing" (Bot API 10.4). The document is capped at 5 MB, which is plenty for a phone. MB
means 10^6 bytes.

## Acceptance

- `tests/acceptance/F8.test.ts` uses the real composition: MCP server, SQLite, grammY poller,
  inbound chain, outbound decorators, and `GitCli` running the real git on a temp repository. It
  runs against the fake Bot API, which now handles multipart `sendDocument`.
  - `/diff`: a document at the fake API, captioned with the summary. The `.diff` holds the
    changes, with a GitHub token and a `.env` value redacted, and the secrets appear nowhere at
    the fake API. Then the three `g1:` buttons. Only the seven read-only invocations ran.
  - `/diff src` narrows the diff to that path.
  - A secret inside a 6 MB file never leaks, and the document is at most 5 MB.
  - No changes: "No changes (branch main)." and no file. Not a repository: says so.
  - Hostile paths (`../outside`, `/etc/passwd`, `--output=…`, `:(glob)**`, `:!src`,
    `C:\Windows`) are refused, and **no process is spawned** (the runner counts them).
  - A Commit tap gives exactly one instruction event for the session. Revert takes two taps.
    Both are audited.
  - A stranger's tap is ignored. A braked tap gets the brake toast. A tap after 30 minutes gets
    "expired". `/diff` works while braked.
  - `g1` data, forged or real, never produces a permission verdict; the open request stays
    pending.
  - `/status` has the git line.
- Unit tests:
  - the path filter (hostile inputs);
  - the porcelain and numstat parsers;
  - the line cut;
  - **the argv allowlist**: every invocation × null device × filter set × path is checked
    against the allowed subcommands, the hardening flags, the path only after `--`, and no
    writing or networking argument;
  - the environment scrub;
  - the callback data (and `g1:` never parsing as `p1:`);
  - the document rendering;
  - redaction before the cap, at every cap position, including a PEM block across the cut and
    a secret past 5 MB;
  - `ShowDiff` (allowlist, busy, stop, refusals, audit without paths);
  - `RequestGitAction` (TTL, skew, brake, revert steps);
  - `ButtonTapHandler` routing;
  - the commands and `/help`;
  - the Telegram gateway upload;
  - `spawnCapturing` (cwd, whole env, cap, abort).
- `bun run check` passes.

## Sequence

```mermaid
sequenceDiagram
    actor P as Owner (phone)
    participant IN as Inbound chain / tap path
    participant D as ShowDiff
    participant G as GitCli (read-only git)
    participant OUT as buildOutbound (redact, then cap)
    participant A as RequestGitAction
    participant CC as Claude Code

    P->>IN: /diff src
    Note over IN: private chat, allowlisted from.id,<br/>rate limit, command (before the brake gate)
    IN->>D: start(chat, path "src")
    Note over D: path policy (no process yet), not busy
    D->>G: read(pathFilter "src", withChanges)
    G->>G: rev-parse, config filters, status, 4 diffs<br/>(argv, no shell, timeout, cap, scrubbed env)
    G-->>D: status + patches
    D->>OUT: sendDocument(changes.diff, summary)
    OUT->>P: 📝 summary + changes.diff (redacted)
    D->>OUT: buttons Commit / Revert / Open PR
    P->>IN: tap g1:c:…
    Note over IN: private, own chat, allowlisted,<br/>rate limit; g1 never reaches ResolvePermission
    IN->>A: execute(commit, issuedAt)
    Note over A: not expired? not braked?
    A->>IN: fixed instruction as owner text<br/>(rate limit, brake gate, audit)
    IN->>CC: channel event
    CC->>P: permission prompts for its git commands (F3)
```

## Manual verification (owner, with a token and a paired account)

Use the throwaway state directory from `docs/flows/F1.md`, in a project that is a git repository
with a few uncommitted changes (one staged, one unstaged, one new file).

1. `/diff`: a document `changes.diff` with the summary as caption, then a message with three
   buttons. Open the file on the phone: staged, unstaged and untracked sections.
2. Put a fake token (`ghp_` + 36 letters) in a changed file: the document shows `[REDACTED]`.
3. `/diff src` (a real folder): only that folder. `/diff ../x`, `/diff -p` and `/diff :/`: refused
   with the reason.
4. Commit all changes, then `/diff`: "No changes".
5. Make a change, `/diff`, tap **Commit**: the toast says sent, the buttons are replaced, the
   session gets the instruction, and Claude asks permission for `git commit`. Deny or approve as
   you like.
6. Tap **Revert**: the buttons become Confirm revert / Cancel. Cancel: nothing is sent. Run `/diff`
   again, Revert, then Confirm: Claude gets the revert instruction and asks before running
   anything.
7. **Open PR** (on a repository with a remote, if you want): Claude asks before pushing.
8. `/stop`, then `/diff`: still works. Tap a button: the brake toast, nothing is sent. `/resume`.
9. `/status` shows the git line.
10. From a directory that is not a repository (no `CLAUDE_PROJECT_DIR`): `/diff` says so.
11. Audit query (F1): `git.diff_sent` rows with counts, and `git.action_requested` rows with the
    action, never a path.
12. **[Linux]** Optional hardening check, in a throwaway repository only: run
    `git config diff.external 'touch /tmp/pwned'`, then `/diff`. `/tmp/pwned` must not appear.

## Open points

- **Needs live verification**:
  - the phone shows the `.diff` file name and caption as expected;
  - how Claude carries out each instruction;
  - whether the "Open PR" wording suits repositories without `gh`.
- A diff is code leaving the PC: redaction is best effort (threat model). Large untracked files
  are listed, not included.
- The instruction goes through the text chain. If a typed "Other…" choice answer is pending
  (F7), the instruction would be taken as that answer, as with a skill tap.
- If the rate limit drops the instruction, the toast still says it was sent (the same as a
  skill tap).
- Submodule changes are not shown in detail (`--ignore-submodules=dirty`).
